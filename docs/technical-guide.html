Run form

spec.yaml shapes the form in three ways:

  • Subject group drop-down. rjsf-overrides replaces the set_string_var field in the Subject Group task group (Var) with a Subject Group Name drop-down. Its EarthRangerEnumResolver transform lists the subject groups of the data source picked under Connect to EarthRanger (depends_on: properties.er_connection.properties.data_source.properties.name). Fields inside a task group are addressed as <group title>.properties.<step id>, so the key is Subject Group.properties.subject_group_name.properties.var. A key naming any other step id matches nothing and is ignored.
  • Comparison period default. rjsf-overrides titles and describes the Comparison Period step (previous_time_range) and defaults its length to the Same as current period preset: previous_time_range.properties.offset.default picks the Preset option, and $defs: PresetPreviousPeriod.properties.preset.default sets the preset inside it.
  • Open settings. Trajectory Segment Filter, BaseMap URLs and Comparison Period have no partial values, so they're on the form for each run. Without a ui:order, sections appear in the order of the steps.

Recompiling

spec.yaml is the source; ecoscope-workflows-subject-historic-current-comparison-workflow/ is generated from it by wt-compiler. Recompile after changing the overrides or the open settings: the form schema is part of the generated package.

./dev/recompile.sh --update   # keeps the lock file and bumps VERSION.yaml
./dev/recompile.sh --install  # a new lock file, and the packages installed

Testing

Each case in test-cases.yaml runs the workflow with its settings:

pixi run --manifest-path pixi.toml -e default bash dev/pytest-cli.sh subject_historic_current_comparison --all
