Troubleshooting

Common issues while configuring, running or changing subject-historic-current-comparison, and how to resolve them.

Configuration & connections

A data source connection fails or times out

Check the server URL and credentials in the connection, and that you can sign in to the same server in a browser with them. The account needs API access to the data the workflow asks for.

The run returns no data

Check the Subject Group Name picked from the drop-down is the group you meant. Both periods need observations, so widen the time range or pick a longer Comparison Period Length if either is short.

The Subject Group Name drop-down is empty

The list comes from the data source chosen under Connect to EarthRanger, so pick the data source first. If it stays empty, that connection can't be reached or its account can't see any subject groups.

Tracks look broken up, or have gaps

Both periods use the Trajectory Segment Filter settings (by default at most 9 km/h, 5 km and 6 hours per segment), so segments longer, slower or faster than that are dropped. Raise the filter's limits on the form for faster or less frequently reporting subjects.

Historic tracks cover the current tracks

p>

Tick Current tracks on top under Track Order and Colors. It's on by default, and a run that leaves it out gets the same behaviour.

A subject's current tracks are missing, or the run fails while colouring tracks

With Use subject colors for current tracks ticked, each subject needs a colour set in EarthRanger. Set one there, or untick the box to use the Current Tracks Color for every subject.

Developing

The Subject Group field is still labelled "Var", or is free text instead of a drop-down

The override key must name the step id inside the task group: Subject Group.properties.subject_group_name.properties.var. Check it against the id under Subject Group in spec.yaml, and that its depends_on points at properties.er_connection.properties.data_source.properties.name, then recompile.

The track colours are plain text fields, or "Current tracks on top" is missing

The overrides must name the steps inside their task group: Track Order and Colors.properties.status_color_columns.properties.<field> and Track Order and Colors.properties.sort_values_by_status.properties.ascending. Check the group title and step ids in spec.yaml match, then recompile.

CI says the generated files differ from the committed ones

Recompile with ./dev/recompile.sh --update and commit the changes in ecoscope-workflows-subject-historic-current-comparison-workflow/.

CI says VERSION.yaml must be greater than main's

Every change needs a new version. --update bumps it: the minor number when the run form is unchanged, the major number when it changed.

A test case fails in CI but works locally

The CI reads each data source's credentials from the repository's GitHub secrets, named in .github/workflows/test.yml. Add the missing ones under Settings → Secrets and variables → Actions.
